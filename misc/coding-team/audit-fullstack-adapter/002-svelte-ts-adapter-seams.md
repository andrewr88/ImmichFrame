# 002 — fullstack adapter: Svelte/TS seams

## Context

Task 001 (commit `aebc290`) delivered `audit/adapters/fullstack.sh` covering the C# half:
84 files, three scan drivers, 265 findings. This task extends **the same file** to the
Svelte/TS frontend, which is why it was named `fullstack.sh` rather than `dotnet.sh`.

Re-read `audit/ADAPTERS.md` for the contract and your own `fullstack.sh` for the established
patterns — the counter/subshell convention, the batch helpers, `audit_cs_diagnostic_category`,
and the `audit_roslynator_analyzer_dir` probe are all shapes to reuse rather than reinvent.

`ARCHITECTURE.md` documents the frontend: SvelteKit 2 / Svelte 5, TypeScript, Vite, ESLint 9
flat config (`immichFrame.Web/eslint.config.js`), `svelte-check` 4, Prettier 3 configured with
tabs. Note its finding that **frontend lint and type-check run in no CI workflow** — this audit
will be the first thing to gate that code, so expect a large first scan.

Decisions already made (do not relitigate):

- **Prettier is excluded.** `npm run lint` is `prettier --check . && eslint .`; only the ESLint
  half becomes a driver. Formatting findings are noise, the same reasoning that kept
  `dotnet format` out of task 001.
- **`npm audit` findings attribute to `immichFrame.Web/package.json`**, exactly as NuGet
  advisories attribute to `Directory.Packages.props`.
- **Everything gets seeded, errors and warnings alike.** Do not filter the first scan down to
  errors. Severity mapping is how volume is managed — the sweep triages on severity, and task
  001 seeded 131 low-severity rows without trouble.

### Comment regex

`audit_trivial_comment_regex` returns one ERE for the whole repo. Widen it to cover `//` (C#,
TS, JS) and `<!-- -->` (Svelte markup).

It must keep failing to match `///`, which is meaningful in **both** languages — C# XML doc
comments and TypeScript triple-slash directives (`/// <reference types="..." />`). The existing
`//([[:space:]]|$)` construction already achieves this; preserve that property and don't let
`/**` JSDoc match either.

### Verify commands

`audit_verify_build_cmd` and `_test_cmd` each return one string, embedded as prompt text and
never executed by the core. Return both toolchains in one line with a short hint to run the one
matching the files under audit — e.g. build: `dotnet build ImmichFrame.sln` and
`npm --prefix immichFrame.Web run build`; test: `dotnet test ImmichFrame.sln` and
`npm --prefix immichFrame.Web run check`. Exact wording is yours; it is read by an agent.

### Scan drivers

`AUDIT_SCAN_TOOLS` becomes `build vulnerable roslynator eslint sveltecheck npmaudit`.

All three new drivers need `immichFrame.Web/node_modules`. It is present now, but on a fresh
clone it is not — **probe for it and report state `missing` with a "run npm ci" notice**, the
way `scan_roslynator` handles a missing analyzer directory. **A driver must never run
`npm install` or `npm ci` itself**; a scan must not mutate dependencies.

**`scan_eslint`** — ESLint 9 flat config. `--format json` gives an array of
`{filePath, messages:[{line, column, severity, message, ruleId}]}`; parse with `jq`.
`severity` is `2` (error) and `1` (warning) — map to `medium`/`bugs` and `low`/`refactoring`
respectively. Carry `ruleId` in the title so findings are identifiable and dedup properly.
Note ESLint exits non-zero when it reports errors, so treat only a hard failure as failure.

**`scan_sveltecheck`** — `svelte-check --output machine` emits one line per diagnostic,
roughly `TIMESTAMP ERROR "path" line:col "message"`. **Verify the exact shape before writing
the parser** — my Roslynator XML description in brief 001 was wrong and cost a round.
Map `ERROR` → `medium`/`bugs`, `WARNING` → `low`/`refactoring`; skip hints. `svelte-check`
needs `svelte-kit sync` to have run (the `check` script does it first).

**`scan_npmaudit`** — `npm --prefix immichFrame.Web audit --json`. Parse `.vulnerabilities`
with `jq`; severity values are `critical`/`high`/`moderate`/`low` → map `moderate` to `medium`.
Category `security`. Attribute every row to `immichFrame.Web/package.json`; for the line
number, grep that file for the package name and use the match, or 0 for a transitive package —
the same approach `scan_vulnerable` already uses against `Directory.Packages.props`. `npm
audit` exits non-zero when vulnerabilities exist, so again only a hard failure is failure.

## Constraints

- **POSIX `sh`, no bashisms** — the adapter is sourced by a `#!/bin/sh` core, and `/bin/sh` is
  `dash` here. Verify with `dash -n`.
- Dependencies remain `sqlite3`, `jq`, `git`, `dotnet`, `curl`, `unzip`, plus `node`/`npm` for
  the new drivers. Nothing else — no `python3`, no `xmllint`.
- Every driver degrades gracefully; a missing tool never fails the scan.
- Scans stay idempotent: a second run on an unchanged tree inserts zero rows.
- **Fix the unscoped globals flagged in 001's review while you are here**: `best`, `best_key`,
  `seg`, `key`, `d` in `audit_roslynator_analyzer_dir` leak into the sourced core's namespace,
  and `key` collides by name with `audit.sh:232`'s sync loop. Harmless today, but this task adds
  more functions to the same file. Prefix them or otherwise make the collision impossible.
- The working tree has in-flight C# work owned by someone else
  (`ImmichFrame.WebApi/Program.cs`, `.../Helpers/ImmichServerVersionChecker.cs`, two files under
  `ImmichFrame.WebApi.Tests/Controllers/`, and untracked `ImmichFrame.WebApi/Helpers/Profiles/`).
  Do not edit, revert, judge, or commit them. Do not run `git add -A`, `git stash`, or
  `git commit`.
- Do not modify any upstream kit file (`audit/*.sh` other than the adapter, `audit/schema.sql`,
  `audit/*.md`, `audit/manifest.json`, `.claude/`). All 21 must keep checksumming clean.
- Raise privileged operations rather than performing them.
